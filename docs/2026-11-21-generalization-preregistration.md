## 실행 순서와 A의 판정

1. **재현부터 확인한다.** 승인·분할 동결 후 첫 추론은 기존 LEVIR test 128쌍 전체다. 원본 가중치 SHA-256은 [출처 기록](../PROVENANCE.md)에 맞춘다. 기존 RGB 정규화, A→B, 256 px 타일, cutoff 0.5, 정렬 끔, 원 영상 전체에서 다시 예측한다. TP/FP/FN 기준값 6,121,218/484,873/716,186과 차이를 적고 F1이 소수 넷째 자리 0.9107로 재현돼야 외부 평가로 진행한다. 등록 실험의 8 px crop 점수와 구분한다. [기존 원본 결과](../outputs/benchmark_test.csv)
2. **외부 기준선 먼저.** FOTBCD validation에서 원본 그대로(0.2 m, cutoff 0.5, 정렬 끔) 모든 지표를 먼저 산출한다. 이 결과로 도메인 저하를 진단한다. 공식 test 기준선은 미리 잠그고 최종 실행의 첫 구성으로 딱 한 번 평가한다. 개발 도중 test 기준선을 먼저 열지 않는다.
3. **해상도 대조.** 동일한 102.4 m 폭에서 축별 512×0.2/0.5를 반올림해 205×205로 면적 평균 축소한다(유효 GSD 약 0.4995 m). 하단·우측을 기존 방식으로 256 배수까지 패딩한 뒤 제거한다. 확률은 원본 격자로 bilinear 복원 후 cutoff를 적용한다. 주 평가는 양 구성 모두 원래 512 격자의 GT에서 한다. B를 움직여도 GT는 A에 둔다. 외부 전체 프레임 평가에서 겹침 밖 후보는 0으로 두고 모든 조건의 분모를 보존한다.
4. **개발과 선택.** train에서 ID의 UTF-8 `SHA256("42/"+image_id)`가 작은 순서로 최대 1,024쌍, validation은 전량을 쓴다. 동점은 ID순. 변경 유무로 추출하지 않는다. 학습 없는 후보는 native/0.5 m × cutoff {0.3, 0.5, 0.7} × 정렬 {끔, B에서 validation으로 선정한 정책}이다. 이동 기준은 0.5 m 격자의 px를 물리거리로 환산한다. 점수가 같은 경우 원본에 가까운 순서(정렬 끔, native, cutoff 0.5, 이후 낮은 cutoff)로 고른다. 평가 단위는 항상 원 영상 쌍이다.
5. **미세조정 1회.** 원본 TinyCD에서 시작해 seed 42, 0.5 m 입력, AdamW(lr 0.0001, weight decay 0.0001), 이진 BCE, 배치 2, 최대 3 epoch로 학습한다. 학습 GT만 최근접 축소하고 패딩은 loss에서 제외한다. 쌍에 같은 수평 뒤집기(p=0.5)를 적용한다. epoch별 validation F1(0.5, 정렬 끔) 최대, 동점이면 이른 epoch로 동결한다. 이 모델과 학습 없는 최선 및 원본을 모두 최종 표에 넣는다. 미세조정 모델은 동일 원본 LEVIR 128쌍에도 cutoff 0.5로 평가해 퇴행을 절대 F1 차이로 보고한다.
6. **원인 진단.** 외부 dev 같은 쌍에 두 해상도·입력 순서·정렬 on/off를 비교한다. 성분 면적·길쭉함, 연도·지역별 P/R과 표본 수, 누락/오경보 예를 기록한다. 방향 정보는 binary에서 알 수 없으므로 dev 원 영상의 눈으로 구별 가능한 신축/철거 사례만 별도 표시한다. 촬영각 메타데이터가 없으면 각도 효과는 미식별로 남긴다. TEST 변화로 원인이나 임계값을 고르지 않는다.
7. **지표.** 픽셀 micro P/R/F1/IoU, 8-연결 GT의 30% 이상을 덮은 객체 비율, 같은 크기의 다른 영상 예측을 seed 42 고정 derangement로 대응한 null, skill=(실측−null)/(1−null)을 보고한다. 기존 면적 bin 경계 100/250/500/1000/2500/5000 LEVIR px를 각각 0.25 m²/px로 환산한다. GT 순도 10% 미만인 예측 성분 수를 평가 면적(km²)으로 나누어 전체와 5 m² 이상을 별도로 표시한다. 크기 bin의 분모가 0이면 NA. [객체 지표](../scripts/scientific_evaluation.py) · [null 구현](../scripts/final_analysis_additions.py)
8. **발표값 비교.** 저자 FOTBCD-Binary 시험표는 현지 학습 F1/IoU 0.900/0.818, LEVIR-CD+ 학습 0.462/0.300을 보고한다. 해당 저자 모델 값으로 표시하고, 데이터 버전·입력 크기·집계·학습 split 차이를 함께 적는다. [저자 비교표와 평가 코드](https://github.com/abdelpy/FOTBCD-datasets/tree/26daefbaec07b5bdd49ee65a84f4113c1913b108)

## B의 독립 검증과 선택

- **자연 어긋남.** FOTBCD validation을 위의 ID 해시순으로 24쌍 선택한다. 모델 출력과 변화 라벨을 가린 상태에서 안정 지상 특징의 SIFT 상호 대응 및 translation RANSAC을 구하고, 사람이 확인할 수 있도록 번호·좌표·잔차와 전후 확대도를 남긴다. 최소 3개 사분면에 걸친 독립 대응점 12개, inlier 비율 0.7 이상, 중앙 잔차 1 native px 이하, 공간적으로 반씩 나눈 두 추정 벡터 차이 1 native px 이하만 참조로 채택한다. 지붕·차량·그림자·신축 윤곽의 대응은 제외한다. 참조 추정에 쓴 지점과 분리한 고정 대응점(사분면별 좌표순 홀짝 분할)에서도 중앙 잔차 1 px 이하를 요구한다. 기준 벡터는 검증 쪽 지점으로 다시 맞추지 않는다. 크기 2 native px 이상인 채택 쌍이 5개 이상이면 보정 전후 잔차(m, px), F1, 보류율을 모든 적격 쌍에 보고한다. 부족하면 수와 탈락 사유를 보고하고 자연 이동 성능 판정을 생략한다. 이 24쌍은 정렬기 선택에 쓰지 않는다.
- **후보.** 기존 방식도 phase peak의 5×5 무게중심을 쓰며 적용할 때 정수로 반올림한다. 이를 대조로 유지한다. 새 후보 두 개는 같은 타일·동의율·품질 게이트에서 (i) 위상 상관 peak의 국소 DFT 10배 업샘플링, (ii) 원 추정에서 시작하는 translation-only ECC(50회, epsilon 1e−5)다. 새 후보는 소수 이동을 bilinear 적용하고 수렴 실패나 기존 게이트 실패 시 B를 그대로 둔다. 허용 길이는 최대 12 px, 적용 하한 후보는 {4, 5, 6} px다. [기존 추정기](../registration.py)
- **선택.** LEVIR validation 64쌍에서 clean 및 (3,3), (5,5), (−4,7)를 주입한다. 공통 유효 영역에서 clean F1 손실 ≤0.002를 먼저 적용한다. 통과한 후보 중 세 이동의 평균 회복률이 최대인 것을 선택한다. 동점은 낮은 중앙 상대오차, 기존 정책, DFT, ECC, 큰 하한 순이다. 기존 정책보다 개선된 적격 후보가 없으면 기존 구성을 유지하고 새 후보 중 최선도 비교용으로 사전 동결한다. 어떤 보정도 제약을 통과하지 못하면 정렬 끔을 선택하고 새 후보의 실패를 기록한다.
- **확인.** 기존 LEVIR test 128쌍에 동일한 네 조건(0,0 포함)을 적용한다. 8 px 기본 crop 안에서 주입 및 역이동 양쪽의 실제 지지 영역을 모든 비교군에 공통 적용한다. 소수 이동은 bilinear의 모든 유효 이웃을 요구한다. 기존 정책도 같은 영역에 재채점해 과거 표와 영역 차이를 보인다. 원본/기존/새 후보/알고 있는 이동량의 역보정 및 보류된 쌍을 모두 포함한다. 회복률=(보정 F1−무보정 F1)/(역보정 F1−무보정 F1), 분모 ≤0이면 NA. 절대 오차 ‖추정−주입‖와 상대 오차 ‖(이동 쌍 추정−동일 clean 쌍 추정)−주입‖의 중앙값을 구분한다. clean의 약 2.2 px는 원 영상의 참 이동을 측량한 값이 아니다. 이미 공개한 LEVIR 결과의 후속 비교임을 명시한다.

## 최종 실행과 보고

승인 이후 각 무거운 단계는 screen 안에서 저장소의 heavy-status 확인 후 heavy-run으로 직렬 실행한다. 최종 추론 전 코드, 데이터 manifest, 가중치 SHA-256, 임계값, 전처리·선택 설정, 패키지 버전을 동결한다. Git에 추적되는 출력은 추론이 모두 끝난 뒤 옮긴다. 시작 시 추적·미추적 소스 변경이 없는지 검사하고, 무시된 작업 디렉터리에 소스 commit, 정규 JSON 설정의 SHA-256, split/weights 해시, git_dirty=false를 결과마다 보존한다. 같은 해시의 완료 행만 재사용하고 중복 키·누락을 검사한다. 외부 test는 원본과 동결한 비교군을 한 번의 잠긴 실행으로 평가하며 결과를 본 뒤 구성을 바꾸지 않는다.

별도 표준 라이브러리 스크립트에서 쌍별 정수 TP/FP/FN을 직접 더해 2TP/(2TP+FP+FN)을 재계산하고 주 평가기와 절대 차이 1e−12 이하를 확인한다. 최종 보고서에는 전체 테스트 출력, 데이터·모델 출처, 실측과 예측 비교, 편차, 한계와 커밋을 넣는다. 사이트에는 게시하지 않고 카드 문구만 제안한다. 데이터·가중치는 Git에서 제외한다.

## 추가 — 사용자 승인 후 실행 전 등록

사용자 요청으로 작업 에이전트와 독립된 리뷰 세션의 Claude가 작성했고 사용자가 검토 후 채택한 FOTBCD test 픽셀 micro-F1 예측은 원본 TinyCD **0.35 (0.25–0.50)**, 미세조정 구성 **0.65 (0.55–0.75)**다. 보고서에서 위 작업 에이전트 예측과 실제 측정값을 같은 표에 싣는다.

FOTBCD 전체판 NEW/DEMOLISHED 폴리곤의 이용 조건이 Binary와 같고 공식 test 979쌍 전체를 라벨 메타데이터로 일대일 대응할 수 있으면 동일한 최종 예측으로 신축·철거 픽셀 recall을 각각 계산한다. 설명용 분석으로 기존 판정 기준을 유지한다. 이용 조건이 다르거나 매칭이 실패하면 허용되는 validation 분석 범위와 그 이유를 명시한다. 시험 영상을 보고 사례를 고르지 않는다.
